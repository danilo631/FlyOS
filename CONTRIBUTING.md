# Contributing to Fly OS

Keep changes small, measurable and easy to rebase on Ubuntu/KDE updates.

- use GPL-compatible code for Fly-owned components;
- do not add proprietary Apple assets;
- prefer upstream settings/APIs before forking a large project;
- document performance claims with before/after measurements;
- test package creation with `./tests/smoke.sh`;
- test ISO changes in a VM before bare-metal installation.
