# Fly OS APT repository

Fly OS 0.11 introduces a first-party archive layout generated by `build/build-apt-repo.sh` and consumed by the `flyos-repo` package.

## Client layout

`/etc/apt/sources.list.d/flyos.sources` uses deb822 syntax and points to the `apt` branch of `danilo631/FlyOS`. The archive public key is installed at `/usr/share/keyrings/flyos-archive-keyring.gpg`.

`fly-repo status` prints the configured source. `fly-repo channel dev|beta|stable` changes only the suite via a narrow privileged helper. Run `sudo apt update` after changing channels.

## Build

```bash
make package
FLYOS_CHANNEL=dev FLYOS_GPG_KEY=<fingerprint> make apt-repo
```

The builder creates `pool/`, `dists/<channel>/main/binary-all/`, `binary-amd64/`, `Release`, and when a signing key is provided, `Release.gpg` plus `InRelease`. The amd64 index intentionally includes `Architecture: all` packages because all current Fly components are architecture-independent. Release metadata includes `Valid-Until` and `Acquire-By-Hash`, and SHA-256 by-hash copies are published for package indexes.

The `flyos-repo` package defaults to `dev` for development/alpha versions, `beta` for beta/RC versions and `stable` for final versions. Builders may override this with `FLYOS_DEFAULT_CHANNEL` when intentionally publishing a build to another channel.

## Signing

Never commit a private archive key. The repository contains only the public key. For GitHub Actions, store an armored private signing key in `FLYOS_APT_PRIVATE_KEY` and its fingerprint in `FLYOS_APT_KEY_FINGERPRINT`. Before a stable 1.0 release, rotate the development archive key to a long-lived production key stored offline or in a dedicated signing service.

## Channels

- `dev`: developer alphas and continuously tested builds;
- `beta`: release candidates with broader hardware validation;
- `stable`: only releases that satisfy the release checklist.

Do not publish a development version into `stable` merely to make it installable.
