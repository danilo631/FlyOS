# Fly OS UX principles

1. **One obvious place first.** Fly Center is the primary control surface; upstream tools are exposed as Advanced controls when needed.
2. **Fast paths stay fast.** Search, launcher, quick settings, app launch and window overview must require few interactions.
3. **State is visible.** Power mode, network, battery, DND, update/reboot state and recovery status should be discoverable without terminal commands.
4. **Effects communicate, not distract.** Blur and motion are allowed, but reduce automatically for accessibility, power saving and constrained hardware.
5. **Actions should be reversible.** Updates snapshot first when possible; experimental effects and kernel features stay optional.
6. **Privacy is a default.** Local search is local; clipboard history is opt-in/session-only; project telemetry is absent by default.
7. **Hardware truth over fake features.** Battery limits, HDR, firmware and acceleration are shown only when supported.
8. **Compatibility without visual dependency.** Applications and drivers can come from the Ubuntu ecosystem without requiring Ubuntu/Kubuntu UX.
